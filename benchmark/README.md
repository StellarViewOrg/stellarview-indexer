# StellarView Database Benchmark

This is a manual, research-only harness. It compares the active PostgreSQL/TimescaleDB write path with an equivalent ClickHouse load over the fixed pubnet range 100 through 104. The repository does not currently contain an explorer read service, so query SQL is defined as a benchmark contract and is run directly against the loaded core tables.

## Reproduce

Requirements: Go, Docker Compose, `psql`, `curl`, and public S3 access.

```bash
./benchmark/scripts/run.sh validate
./benchmark/scripts/run.sh run
```

The runner writes raw JSON and TSV artifacts under `benchmark/results/`. The database services use ports `55432` and `58123` and volumes dedicated to this benchmark. `run.sh clean` removes those volumes and results.

The PostgreSQL load reuses `cmd/indexer migrate` and `cmd/indexer s3backfill`, with `WORKER_COUNT=1` by default. ClickHouse receives exports from the same PostgreSQL-loaded logical rows. This makes the storage and query comparison use identical rows; the measured ClickHouse load is a bulk-load measurement, not a claim that it replaces the production decoder.

The fixed range is deliberately small because Docker is not available in every development environment. It is the range already exercised by `internal/pipeline/s3backfill_test.go`. The manifest records the SDK-resolved S3 object layout and is regenerated by the manifest command when object-level checksums are required.

`ReplacingMergeTree` tables intentionally use `FINAL` only for correctness comparisons. Raw and `FINAL` counts must both be recorded after replaying rows to expose asynchronous deduplication.
